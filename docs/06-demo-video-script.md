# 3분 시연 영상 시나리오

## 목표

예선 영상은 완제품 외관보다 “임베디드 루프가 실제로 돈다”는 증거가 중요하다. 화면 녹화만 보여주지 말고, 카메라에 Raspberry Pi, NFC 리더, 프린터, 태그, 출력물을 함께 잡는다.

## 0:00-0:20 문제 정의

멘트:

> 재난대피소에서는 같은 가구의 중복 수령, 잘못된 물품 지급, 재고 불일치가 동시에 발생할 수 있습니다. ReliefCheck는 가구와 물품을 서로 다른 NFC 리더로 분리 인식하고, 인터넷 없이 로컬 정책으로 지급 가능 여부를 판정하는 현장형 단말입니다.

화면:

- 전체 장치 전면
- 왼쪽 가구 NFC, 오른쪽 물품 NFC, 중앙 물품 확인 영역 강조

## 0:20-1:10 정상 지급

순서:

1. 가구 카드를 왼쪽 NFC에 태그
2. 물품 태그를 오른쪽 NFC에 태그
3. 화면에서 가구/물품/정책 판정이 순서대로 바뀌는 장면
4. 승인 후 감열프린터 출력
5. 출력물의 거래번호와 화면 거래번호 일치 확인

핵심 멘트:

> 지급 결정은 먼저 SQLite에 원자적으로 저장되고, 출력은 별도 상태로 관리됩니다. 프린터가 실패해도 지급 거래가 중복 실행되지 않습니다.

## 1:10-1:50 중복 방지

순서:

1. 새 세션 시작
2. 다른 가구 또는 같은 가구로 이미 지급된 물품을 다시 태그
3. `D002 동일 물품 재처리` 거절 표시
4. 같은 가구가 정책 한도를 넘는 물품을 요청하면 `D001` 표시

핵심 멘트:

> ReliefCheck는 가구별 한도 초과와 동일 개별 물품 ID 재처리를 모두 차단합니다. 단순 재고 차감이 아니라 정책 기반 배분 판정입니다.

## 1:50-2:25 예외 상황

순서:

1. 물품 태그를 가구 리더에 태그해서 `R001` 표시
2. 미등록 태그를 입력해서 `H001` 또는 `I001` 표시
3. 카메라 불일치 상태로 `V001` 표시

핵심 멘트:

> 두 NFC 리더의 역할을 물리적으로 분리해서 현장 입력 실수를 줄이고, 카메라 교차검증으로 태그와 실물이 다른 상황을 막습니다.

## 2:25-2:50 오프라인/복구성

순서:

1. 네트워크를 끈 상태에서 `/health` 또는 화면 정상 동작 확인
2. 최근 거래와 재고가 로컬 DB에 남아 있는 장면
3. 프린터 실패 시 `print_status=FAILED` 후 재출력 흐름 설명

핵심 멘트:

> 재난 현장에서는 인터넷이 끊길 수 있기 때문에 핵심 기능은 모두 로컬에서 동작합니다.

## 2:50-3:00 마무리

멘트:

> ReliefCheck의 차별점은 듀얼 NFC 입력, 오프라인 정책 판정, 거래 무결성, 현장 증빙 출력이 하나의 임베디드 루프로 연결된다는 점입니다.

마지막 화면:

- 전체 장치
- 출력물
- `/health` 장치 상태
