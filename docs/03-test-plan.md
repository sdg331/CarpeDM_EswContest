# ReliefCheck 시험 계획

## 소프트웨어 단위 테스트

```bash
python -m unittest discover -s tests
```

확인 항목:

- 등록 가구와 준비된 물품은 승인된다.
- 비활성 가구는 거절된다.
- 카메라 불일치는 `V001`로 거절된다.
- 승인 후 물품 상태가 `DISTRIBUTED`로 바뀐다.
- 동일 물품 재처리는 `D002`로 거절된다.
- 잘못된 리더 입력은 거래를 만들지 않고 `R001`로 거절된다.

## 로컬 MVP 시연 테스트

```bash
python -m reliefcheck.main --reset-seed
```

브라우저에서 `http://127.0.0.1:8008` 접속 후 다음 순서로 확인한다.

1. `HH-001` 가구 카드 선택
2. `ITEM-RICE-001` 물품 태그 선택
3. 승인 결과와 확인증 파일 생성 확인
4. 새 세션 시작
5. 다른 가구로 같은 물품 태그 재처리
6. `D002` 거절 확인
7. 카메라 일치 체크 해제 후 새 물품 태그 처리
8. `V001` 거절 확인

## 결선/전시용 신뢰성 테스트

| 항목 | 목표 | 방법 |
|---|---|---|
| NFC 정상 인식률 | 99% 이상 | 등록 태그 100회 반복 |
| 잘못된 리더 감지 | 100% | 가구/물품 태그 교차 입력 |
| 중복 지급 차단 | 100% | 동일 가구 한도 초과 반복 |
| 동일 물품 재처리 차단 | 100% | 지급 완료 item_id 재태그 |
| 프린터 실패 복구 | 100% | 프린터 분리 후 승인, 재출력 |
| 전원 재인가 복구 | 100% | 승인 후 강제 재시작, DB 확인 |
| 연속 시연 성공률 | 95% 이상 | 50회 End-to-End 반복 |
