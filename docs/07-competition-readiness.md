# ReliefCheck 대상급 시연 완성도 점검표

## 1. 심사위원이 첫 5초에 봐야 할 것

- 재난 대피소 현장에서 구호물자 중복 지급을 차단하는 임베디드 시스템이다.
- 가구 카드와 물품 태그를 서로 다른 NFC 리더로 분리 인식한다.
- 네트워크가 끊겨도 Raspberry Pi 내부 SQLite 원장에 거래를 남긴다.
- 승인/거절 사유가 코드와 체크리스트로 남아 운영자가 설명할 수 있다.
- 프린터, 카메라, NFC, DB 상태가 같은 콘솔에서 확인된다.

## 2. 현재 코드로 바로 시연 가능한 장면

| 장면 | 확인 위치 | 판정 포인트 |
|---|---|---|
| 정상 지급 | 현장 지급 탭 | 가구 인증, 물품 인증, 정책 판정 순서가 분리된다. |
| 동일 물품 재태그 차단 | 정책 판정 탭 | `D002`로 거절되고 거래 원장에 남는다. |
| 가구별 한도 초과 차단 | 정책 판정 탭 | `D001`로 거절되고 허용 수량과 기지급 수량이 보인다. |
| 카메라 불일치 차단 | 현장 지급 탭 | `V001`로 거절된다. |
| 운영 현황 확인 | 운영 대시보드 탭 | 승인, 거절, 중복 차단, 재고 압박도, 감사 로그가 보인다. |
| 장치 상태 확인 | 장치 진단 탭 | NFC, 프린터, 카메라, SQLite 상태가 분리 표시된다. |
| SW 검증 체계 | SW 검증 탭 | 실장비 미연동 상태에서도 자동 시나리오 10개와 준비도 점수가 보인다. |

## 3. 실장비 미연동 시 소프트웨어 완성도 전략

현재 작업 환경에서는 ACR1252U, 프린터, 카메라를 직접 연결할 수 없으므로 물리 성능 수치를 주장하지 않는다. 대신 `SW Evidence Mode`를 기준으로 다음을 증명한다.

- 같은 정책 엔진으로 정상 승인, 동일 물품 재태그, 가구별 한도 초과, 카메라 불일치, 미등록 UID, 잘못된 리더 입력을 검증한다.
- 프린터 실패를 강제로 주입해도 승인 거래가 보존되고 `print_status=FAILED`로 분리되는지 확인한다.
- 공개 API에서 확인증 파일 경로가 제거되는지 테스트해 개인정보/파일 경로 노출 위험을 줄인다.
- `reports/sw-evidence-summary.md`와 `reports/sw-evidence-latest.json`에 실행 가능한 증거를 남긴다.
- 실장비 복귀 후에는 같은 시나리오를 수동 입력 대신 NFC/프린터/카메라 입력으로 바꿔 반복 측정한다.

## 4. 대상급으로 보이기 위해 반드시 채워야 할 실측값

| 항목 | 목표 | 제출 전 증거 |
|---|---:|---|
| NFC 등록 태그 반복 인식 | 100회 중 99회 이상 | 실험 영상, 회차별 CSV |
| 잘못된 리더 감지 | 100% | 가구/물품 태그 교차 입력 로그 |
| 중복 지급 차단 | 100% | `D001`, `D002` 거래 원장 캡처 |
| 프린터 실패 복구 | 100% | 실패 후 재출력 로그와 확인증 |
| 전원 재인가 복구 | 100% | 재시작 후 SQLite 거래 보존 캡처 |
| 연속 시연 안정성 | 50회 중 48회 이상 | `reports/experiment-summary.md` |

## 5. 발표 시 강조 문장

- ReliefCheck는 물품을 많이 나눠주는 시스템이 아니라, 제한된 구호물자가 공정하게 지급되도록 현장 오류를 줄이는 시스템이다.
- 단순 NFC 출석 체크가 아니라, 가구 자격, 물품 개별 태그, 가구별 지급 한도, 재고, 카메라 검증을 한 번의 정책 판정으로 묶었다.
- 출력 실패가 나도 승인 거래는 이미 원장에 남기 때문에 프린터 문제로 중복 지급이 발생하지 않는다.
- 서버 없이도 Raspberry Pi 한 대에서 동작하도록 구성해 재난 현장의 네트워크 불안정성을 전제로 설계했다.
- 현재는 실장비 물리 성능을 과장하지 않고, 소프트웨어 로직과 장애 대응 체계를 먼저 재현 가능한 증거로 완성했다.
